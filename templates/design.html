Introduction

In Week 3, we focused on giving the website a consistent visual design. After organizing the pages with Jinja template inheritance, the next step was to create a shared stylesheet and define the design decisions that would be reused across the whole website.

The main idea was to define the site's visual identity once and then reuse it on every page. This makes the website more consistent, easier to modify, and easier to maintain.

What We Did

1. Created a Shared Stylesheet

Instead of styling every HTML page separately, we created one stylesheet named style.css inside the static/ folder. The stylesheet is linked once from the shared base.html template, so every page that inherits from it automatically receives the same visual design.

2. Defined Design Tokens with CSS Variables

We used CSS custom properties inside :root to store repeated design decisions such as colors, spacing, typography, and corner radius. 

:root {
    --primary: #2563eb;
    --secondary: #64748b;
    --text: #0f172a;
    --background: #ffffff;
    --spacing: 1rem;
    --radius: 8px;
}

These variables can then be reused throughout the stylesheet with var(...). This means that changing one value in :root can update the design in many places.

3. Styled the Shared Page Structure

The CSS was used to style the elements defined by the shared template, including the header, logo and title, navigation menu, main content area, headings, links, lists, page sections, and footer.

Because all pages use the same template structure, styling these common elements once gives the entire portfolio the same visual identity.

Design Principles

Colors

A consistent color palette was selected for the website. The colors were stored as CSS variables so they could be reused throughout the different pages.

Typography

Typography was kept consistent by defining shared font choices, heading sizes, text sizes, and spacing. This helps the content remain readable and gives the website a coherent appearance.

Spacing and Corners

Shared spacing values and border-radius values were used to create consistent gaps, padding, and rounded corners throughout the site.

Layout with Flexbox and Grid

Navigation with Flexbox

The navigation menu was improved using CSS Flexbox. The navigation items can be arranged in a row, spaced consistently, and vertically aligned. On smaller screens, the items can wrap instead of causing horizontal overflow.

Weekly Work with CSS Grid

The Weekly Work list was designed as a responsive grid. CSS Grid allows the items to automatically move between columns depending on the available screen width. 

.weekly-list {
    display: grid;
    grid-template-columns: repeat(auto-fit, minmax(240px, 1fr));
    gap: 1rem;
}

Responsive and Mobile-First Design

The stylesheet was designed using a mobile-first approach. The default CSS rules target smaller screens first, and media queries are then used to adapt the layout for wider screens.

  • Text remains readable on small screens.
  • The navigation can wrap instead of overflowing.
  • The main container becomes wider on larger screens.
  • The Weekly Work grid adapts to the available space.
  • The website should not create unwanted horizontal scrolling.

One of the important checks was making sure the website still works on a 375px-wide mobile screen.

How AI Was Used

AI was used as an implementation assistant rather than as the designer. The design decisions were defined first, and then AI was instructed to generate the CSS according to those decisions and the existing HTML.

The stylesheet was required to use vanilla CSS only. AI was instructed not to rewrite the HTML or invent new classes, attributes, or wrapper elements. If an HTML change was genuinely necessary, it had to be identified first so that the change could be made deliberately.

Testing and Verification

After generating the stylesheet, the Flask application was tested in the browser to verify that the design worked correctly across the website.

  • Checked that the layout matches the shared template.
  • Checked that the chosen colors and fonts are applied.
  • Checked that all pages use the same design.
  • Tested the navigation at different screen widths.
  • Tested the Weekly Work grid as the browser width changes.
  • Checked the mobile layout for horizontal overflow.

Important Week 3 Concepts

One Structure, One Style

Jinja template inheritance allows the common HTML structure to be written once, while one shared stylesheet controls the common appearance of the pages.

CSS Variables

CSS variables allow design values to be defined once and reused throughout the stylesheet. This is the basic idea behind design tokens in larger design systems.

AI-Assisted Development

The important skill is not simply generating CSS with AI. The goal is to give the AI clear constraints, review its output, test it in the browser, and understand the final code.

Key Takeaway

Week 3 showed how a website can move from a collection of separate HTML pages to a consistent design system. Jinja provides the shared structure, while CSS variables and one stylesheet provide the shared visual identity. AI can help implement the design, but the developer remains responsible for directing, checking, and understanding the result.
